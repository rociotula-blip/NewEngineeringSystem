# V0.5.1 更新紀錄｜移除工程初始設定的管理精度與分段長度

日期：2026-11-23  
使用者依 V0.5 GUI 截圖確認：**建立新工程的初始設定畫面不需要「管理精度」與「分段長度（公尺）」兩個欄位，也不需要 batch/station 提示文字。**

## 修正後行為

- 新增工程畫面保留工程代碼、名稱、契約編號、開工、預定完工與實際竣工日期。
- 施工里程是否需分段、分段長度多少，留到實際施工里程／工區作業才決定，不在整個工程建立時強制選擇。
- 同一工程可以有單純批次紀錄、以及需要樁號分段的其他批次，兩者不相互排斥。
- 正式代碼不變：批次 `YYYMMDD-RRDL-BBB`；分段 `YYYMMDD-RRDL-BBB-SSS`。內路肩 I，外路肩 E。

## 已完成的本地程式修改

1. `main.py`：移除兩個控制項及說明；新增工程時不傳入模式／分段長度；開啟工程的提示也不再顯示管理精度。
2. `project_manager.py`：建立新工程不需管理精度或分段長度，保留老呼叫參數相容；資料庫保留 legacy preference 欄位，但不以它作工區分段的強制判定。
3. `database/schema.sql`：移除全工程強制 station／batch 的資料庫觸發器；分段決定權在施工批次層級。
4. `database/init_db.py`：schema 版本更新為 6；開啟既有 schema V5 工程時，先建立 `engineering.sqlite3.before_v051.bak`，再移除舊模式的限制觸發器。拒絕靜默遷移 V0.2、V3.0 或未知 DB。
5. 測試結果：**9 項 Python/SQLite 自動測試通過**，包括升級前備份及保留既有工程資料。
