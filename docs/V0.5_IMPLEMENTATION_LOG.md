# V0.5 開發紀錄：一工程一資料庫與新批次編碼

紀錄日期：2026-11-23  
版本：V0.5 初始可執行程式套件（Python 3.10+ / tkinter / SQLite）

## 經確認的核心決策

1. **一個工程、一份獨立 SQLite 檔案**；同一套程式可切換多個工程。
2. 主程式另有 `project_registry.sqlite3`，僅存工程清單、工程代碼與獨立工程資料庫路徑；不存跨工程施工數量。
3. **編碼採 V0.4**：工區批次 `YYYMMDD-RRDL-BBB`；工區內樁號 `YYYMMDD-RRDL-BBB-SSS`。
4. 同日同車道分兩三個施工區域，就分為 BBB `001`、`002`、`003`；每工區的 SSS 各自從 `001` 開始。
5. `I` 內路肩、`E` 外路肩；停用 O。
6. 工程可設定批次模式或批次＋樁號模式。只有分段模式才建立 `work_stations`。

## 本次實際完成的本地程式

交付檔名：`NewEngineeringSystem_V0.5.zip`（在本次 ChatGPT 對話中提供）。

- `main.py`：Tkinter 工程清單／新增／開啟工程初始畫面。
- `project_manager.py`：建工程專用資料夾、SQLite、工程索引；建立與開啟期間驗證資料版本與一致性。
- `database/schema.sql`：33 張應用表格，強制每個工程 DB 只有一筆工程主檔，更新 16 字元批次與 20 字元樁號檢核。
- `database/init_db.py`：schema v5；只新增資料庫或開啟相同版本資料庫，拒絕靜默覆蓋 V0.2／V3.0。
- `database/batch_codes.py`：正規化編碼、連字號、工區批次流水號、路肩、切段、末段與新增記錄。
- `tests/test_v05.py`：7 項隔離測試，**全部通過**。檢驗不同 DB 使用同批次碼、同日第二工區、工區內分段、路肩 E、重疊、舊資料庫拒絕、日期檢核、模式隔離、重開資料保存與 schema 完整性。

**注意：目前只有本地 ZIP 交付已完整包含上述 Python／SQL 原始碼；GitHub 上這份紀錄不代表全部程式碼已提交。** 後續應將套件中的源碼加入本專案版本管理，測試可用 `python -m unittest discover -s tests -v`。
