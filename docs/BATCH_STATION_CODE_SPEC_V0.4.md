# 施工編碼正式規格 V0.4｜日期－車道－施工工區批次－樁號序號

日期：2026-11-23。**本規格取代 V0.3 的無分隔符號顯示格式**，維持兩層流水號的設計原則。

## 正式顯示格式

`YYYMMDD-RRDL-BBB-SSS`

| 欄位 | 例子 | 意義 |
|---|---|---|
| `YYYMMDD` | `1151123` | 民國年月日，7 碼 |
| `RRDL` | `01S3` | 國道 01、南向 S、第 3 車道，4 碼 |
| `BBB` | `001` | **施工工區批次**流水號，3 碼 |
| `SSS` | `001` | **該批次內樁號／分段**序號，3 碼 |

注意：使用者明確指定各欄以 `-` 分隔，**連字號是新正式顯示編碼的一部分**，不是單純示意。

- **批次模式**：`1151123-01S3-001`（16 字元，含兩個分隔符）。
- **批次＋樁號模式**：`1151123-01S3-001-001`（20 字元，含三個分隔符）。
- 第二工區第一段：`1151123-01S3-002-001`。
- 第三工區第一段：`1151123-01S3-003-001`。
- 第一工區第二段：`1151123-01S3-001-002`。
- 內路肩第一工區：`1151123-01SI-001`；外路肩第一工區：`1151123-01SE-001`。

## 核心語意

**一天有幾個彼此獨立的施工工區，就以 `BBB` 區分 001／002／003；不因增加樁號就增加工區批次。** 同一工區內需要按 50m、100m 或自訂長度細分，才以 `SSS` 區分。只需要施工批次的工程可省略 `-SSS`。

- `RRDL` = 道路兩碼 `RR`（如 01／03）＋方向 `N/S` ＋ 車道 `1～9/I/E`。
- `I` = 內路肩；`E` = 外路肩；**O 禁用**，避免與零混淆；最外側行車車道不等於外路肩。
- 樁號序號並非公里數；每筆批次與分段的實際起訖里程另外保存。
- 工程可以選擇批次管理、或批次＋分段管理；兩者共用同一資料庫，以工程／批次內部 ID 連接施工、試驗、日誌、估驗與照片。

## 資料庫與程式的待辦事項

1. `work_batches.batch_no` 應儲存 `YYYMMDD-RRDL-BBB`（**16 字元**），並將 `batch_sequence` 作為獨立欄位。
2. `work_stations.station_no` 應儲存 `YYYMMDD-RRDL-BBB-SSS`（**20 字元**），獨立保存 `station_sequence`。
3. 日期、道路、方向、車道、工區批次及樁號序號都要分欄儲存並建立唯一性／關聯檢核，編碼由程式統一組合，不靠字串解析作為主要資料模型。
4. 工程可僅記錄工區批次（`station_id` 可為 NULL）；採分段模式才建立 `work_stations`。
5. 修正之前 V0.2 的 SQLite schema、產碼工具與驗證器，並就新編碼、同日多工區、重複限制、跨工程及里程分段進行**重新測試**。
6. V0.2 開發套件的舊編碼與測試結果不得當成 V0.4 已經實作通過；目前**正式規格已定稿、程式實作尚待更新**。

## 設計沿革

- V0.2：將 11 碼前綴誤作完整施工批次，已作廢。
- V0.3：確認三碼 `BBB` 是工區批次，`SSS` 是該批樁號；但字串格式尚未依四段加上分隔符號。
- **V0.4：使用者明確確認 `yyyymmdd-車道-施工工區批次-樁號序號`，本版以每段 `-` 分隔作為正式規格。**
